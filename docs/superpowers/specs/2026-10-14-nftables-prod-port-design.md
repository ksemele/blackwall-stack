# nftables: prod firewall as code — design

Date: 2026-10-14
Module: blackwall-eye
Status: approved in chat, pending spec review

## 1. Goal

The production host's firewall is still hand-installed from a local,
git-ignored directory (`hosts/<host>/`): a base table, a Cloudflare origin
filter generated by a refresh script, a systemd timer and an
`nftables.service` drop-in. Make it reproducible from the repository with one
`ansible-playbook` run, while the public repository stays generic: no domains,
addresses or address lists of real hosts. Host values live in a git-ignored
local inventory.

Success:

- The roles applied to the prod host produce the same rules that run there
  today (checked locally, before anything touches prod).
- The lab keeps working: `bw-check nft` passes; the new `bw-check cf-wall`
  passes on `black-host-01`.
- The prod host is applied by the owner, not by the agent.

## 2. Context

- Prod: RHEL family, already migrated from firewalld; runs podman (netavark
  owns `ip nat` / `ip filter`); nginx in a container behind Cloudflare.
- Lab: Ubuntu 22.04 containers under Docker; the `nftables` role renders
  `inet blackwall_base` (input drop, public/restricted ports, forward policy
  `accept`) and an `nftables.conf` that includes `/etc/nftables.d/*.nft`
  without a global flush.
- Manual prod files: `blackwall-base.nft` (adds podman anti-spoof, container
  DNS, `ct status dnat accept`, container egress, forward policy drop, a
  restricted set for port 9999), `blackwall-wall.nft` (prerouting -150,
  CF prefixes + admin allow on 80/443, generated by `blackwall-cf-refresh`),
  `blackwall-cf-refresh.{service,timer}`, `/etc/default/blackwall-cf-refresh`,
  and a drop-in that removes `flush ruleset` from reload/stop.

## 3. Approach

Two independent roles (chosen over one role with a switch, and over rendering
the Cloudflare filter from Ansible):

- `nftables` — the base firewall, extended for RHEL and podman.
- `cf-wall` — the Cloudflare origin filter: deploys the refresh script, its
  timer and config; the script keeps generating the rules on the host, so
  prefixes stay fresh without Ansible.

They meet only at `/etc/nftables.d/*.nft`: the base config includes every file
there, so role order does not matter and `cf-wall` is optional per host.

## 4. Role `nftables` (changes)

### 4.1 OS support

- Package via `ansible.builtin.package`.
- Config path by family: `nft_conf_path` defaults to `/etc/nftables.conf`
  (Debian) or `/etc/sysconfig/nftables.conf` (RedHat), chosen from
  `ansible_os_family`.
- `nftables.conf.j2` keeps the no-flush include of `/etc/nftables.d/*.nft`.

### 4.2 Service drop-in (both families)

`/etc/systemd/system/nftables.service.d/blackwall.conf`:

```ini
[Service]
ExecReload=
ExecReload=<nft> -f <nft_conf_path>
ExecStop=
ExecStop=-<nft> delete table inet blackwall_wall
ExecStop=-<nft> delete table inet blackwall_base
```

Stock reload/stop run `flush ruleset` on both families and wipe tables the
role does not own (netavark on prod, Docker NAT in the lab). `daemon-reload`
via handler before the service is (re)loaded.

### 4.3 Variables (new ones optional; defaults keep the lab unchanged)

| Variable | Default | Meaning |
|---|---|---|
| `nft_podman` | `{}` | `{net: <cidr>, if: <bridge>}`; when set, adds the podman rules below |
| `nft_forward_policy` | `accept` | prod uses `drop` |
| `nft_restricted[].name` | `src_<port>` | optional set name |
| `nft_log_drops` | `true` | now also logs forward drops |

With `nft_podman` set, the template adds:

- input: `iifname <wan> ip saddr <net> counter drop` (anti-spoof, before any
  rule that trusts the subnet); `iifname <if> ip saddr <net> udp/tcp dport 53
  counter accept` (container DNS to aardvark-dns);
- forward: `ct status dnat counter accept` (published ports after DNAT);
  `oifname <wan> ip saddr <net> counter accept` (container egress).

Rule order and comments follow the prod file; the "why" comments move into
the template.

### 4.4 Equivalence check (local only)

`blackwall-eye/tools/nft-equiv` takes an inventory, a host and a reference
`.nft` file. It renders the base template for that host (local
`ansible -m template`), loads the rendered file and the reference file one
after another into a throwaway `--cap-add NET_ADMIN` container with nftables,
and diffs `nft list table inet blackwall_base` for both — nft's own listing is
the normal form, so comments, ordering of set elements and whitespace do not
matter. Exit 0 when the listings match. It is run by hand against
`hosts/prod.yml` and the current prod file; nothing host-specific is
committed.

## 5. Role `cf-wall` (new)

### 5.1 Installs

- `/usr/local/sbin/blackwall-cf-refresh` — the existing script; header made
  host-neutral; ports read from `PORTS` (default `80 443`) instead of being
  hard-coded.
- `blackwall-cf-refresh.service` / `.timer` — weekly, `RandomizedDelaySec=6h`,
  `Persistent=true`.
- `/etc/default/blackwall-cf-refresh` from a template.

### 5.2 Variables

| Variable | Default | Meaning |
|---|---|---|
| `cfwall_ports` | `[80, 443]` | filtered TCP ports |
| `cfwall_admin_allow` | `[]` | sources allowed straight to the origin |
| `cfwall_wan_if` | `""` | empty = from the default route |
| `cfwall_nginx_container` | `""` | empty = skip nginx real_ip |
| `cfwall_realip_out` | `""` | host path of `cf-realip.conf` inside the mounted conf.d |
| `cfwall_min_v4` / `cfwall_min_v6` | `10` / `5` | sanity floor for fetched prefixes |

### 5.3 Behaviour

- First install (no `/etc/nftables.d/blackwall-wall.nft`): run the script once,
  so the filter is not open until the first timer tick.
- Existing install: run the script only when the script or its config changed
  (handler). A plain re-run does not call cloudflare.com and does not touch the
  live rules.
- Rollback: `nft delete table inet blackwall_wall` + disable the timer
  (documented in the role README).

## 6. Inventory and playbooks

- `hosts/prod.yml` (git-ignored): the prod host, group `cf_wall`, all values
  (WAN interface, podman net/bridge, restricted 9999 set, admin allow, nginx
  container and real_ip path).
- `ansible/playbooks/nftables.yml` — unchanged entry point for the base role.
- `ansible/playbooks/cf-wall.yml` — `cf-wall` on group `cf_wall`.
- `ansible/playbooks/verify-cf-wall.yml` — table `inet blackwall_wall`
  present, `cf_v4`/`cf_v6` non-empty, `nft -c` on the generated file passes,
  timer enabled.
- Lab: `cf_wall` group with `black-host-01`; `bw-lab provision cf-wall`,
  `bw-check cf-wall`. The lab does not use 80/443, so the filter changes
  nothing there.

## 7. Testing

- Lab: `bw-lab provision eye` + `bw-check nft` (base unchanged by default);
  `bw-lab provision cf-wall` + `bw-check cf-wall`.
- Drop-in: in the lab, `systemctl reload nftables` and `systemctl stop
  nftables` keep Docker's NAT table (container DNS still resolves).
- Prod equivalence: section 4.4, by hand, before the owner applies the roles.

## 8. Docs

- READMEs of both roles, `tests/README.md` (new provision target and check),
  `blackwall-eye/STATUS.md`.
- The local `hosts/<host>/README.md` gets a note that the roles are now the
  source of truth (local only).

## 9. Out of scope

- Applying the roles to prod (owner does it).
- IPv6 admin allow, auto-update of the 9999 source list, origin IP rotation,
  Cloudflare Tunnel.
- Managing the nginx container itself.
